# AGENTS.md

## What this is

VulnRadar — a fork-and-go, GitHub-native vulnerability intelligence tool (Python 3.11+). It downloads CVE data (cvelistV5 ZIP, NVD feeds), filters against `watchlist.yaml`, enriches with CISA KEV / EPSS / PatchThis, and outputs a Markdown report + JSON via hourly GitHub Actions. `notify.py` turns new critical findings into GitHub Issues and Feishu webhook alerts.

## Commands

```bash
make dev          # install editable + dev deps + pre-commit hooks
make test         # pytest -v --tb=short
make lint         # ruff check .
make fmt          # ruff format . && ruff check --fix .
make typecheck    # mypy etl.py notify.py vulnradar/ --ignore-missing-imports
make etl          # python etl.py
make notify       # python notify.py --in data/radar_data.json
python scripts/validate_watchlist.py   # CI runs this before anything else
```

CI matrix is Python 3.11 and 3.12; both must stay green. Note: CI's mypy step is non-blocking (warning only), but keep it clean anyway.

## Architecture & boundaries

- **`etl.py` and `notify.py` are backward-compat shims, not real code.** All logic lives in `vulnradar/`. The shims re-export package symbols because existing GitHub Actions workflows and external `from etl import …` imports depend on them — do not rename or remove re-exported symbols, and put new logic in the package.
- `vulnradar/` layout: `cli.py` (argparse, `main_etl`/`main_notify`), `config.py` (Pydantic watchlist models), `downloaders.py` (requests + tenacity, sequential), `async_downloaders.py` (aiohttp, used by `--parallel`), `parsers.py` (CVE V5 parsing, watchlist matching, risk scoring), `enrichment.py` (KEV/EPSS/PatchThis/NVD merge), `report.py` (Jinja2 report), `state.py` (`StateManager` for alert dedup).
- Pipeline flow: downloaders → parsers → enrichment → `data/radar_report.md` + `data/radar_data.json` → notifications.
- `data/` contents (`radar_report.md`, `radar_data.json`, `state.json`, `vendors/`) are **auto-generated by workflows** — never hand-edit.
- Notification providers use the Strategy pattern (`vulnradar/notifications/base.py`). To add one: new file subclassing `NotificationProvider` (implement `send_alert`, `send_summary`, `send_baseline`), then register it in `vulnradar/notifications/__init__.py` (`load_providers()` and, for per-severity routing, `load_routed_providers()`).
- Report format changes go in `vulnradar/templates/report.md.j2` (Jinja2), not hardcoded in `report.py`.
- Watchlist matching behavior (substring/exact/regex, thresholds, per-severity notification routing) is configured in `watchlist.yaml` and validated by Pydantic in `config.py`; `watchlist.d/*.yaml` files are merged at runtime.

## Conventions

- Ruff: line-length 120, target py311, rules `E,F,I,B` (E501/B008/F401 ignored). isort first-party: `etl`, `notify`, `vulnradar`.
- mypy is lenient by design (`disallow_untyped_defs = false`, `ignore_missing_imports = true`), but `warn_unused_ignores = true` — no stale `# type: ignore`.
- Tests are fully offline: fixtures in `tests/conftest.py` build sample watchlists and CVE V5 JSON in `tmp_path`. Don't add tests that hit the network.
- Windows dev environments exist (this workspace); code must stay cross-platform — use `pathlib.Path`, avoid shell-only assumptions.

## Gotchas

- `README.md` has `<!-- METRICS START -->` / `<!-- METRICS END -->` markers auto-updated by `scripts/update_readme_metrics.py` — never hand-edit between them.
- `watchlist.yaml` is the user's live config; `watchlist.example.yaml` is the documented reference. CI validates both.
- GitHub Actions CI runs only on `RogoLabs/VulnRadar`, not forks (`if: github.repository == …`) — expected to show as skipped on fork PRs.
- State/dedup semantics matter: first run is a silent baseline; afterwards only *new* critical CVEs alert. Changes to `state.py` or notify dedup logic can cause alert spam — run `python notify.py --dry-run` to check.
